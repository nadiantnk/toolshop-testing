## BUG-003: У авторизованного пользователя не загружаются данные профиля
| Поле | Значение |
| --- | --- |
| **Компонент** | Авторизация, личный кабинет |
| **Severity** | Major |
| **Priority** | High |
| **Окружение** | Windows 11, Brave 1.93.132, Firefox 153.0.1 |
| **URL** | https://with-bugs.practicesoftwaretesting.com/#/account |
| **Воспроизводимость** | Всегда |

**Предусловия:**
Пользователь авторизован под аккаунтом: логин: customer2@practicesoftwaretesting.com  Пароль: welcome01

**Шаги воспроизведения:**
1. Войти в аккаунт с валидными данными.
2. Открыть страницу "Мой аккаунт" (My account).
3. Посмотреть на верхнее меню навигации, открыть DevTools - Console - Network.

**Фактический результат:**
В меню навигации и в блоке аккаунта данные пользователя не отображаются (текст «User Data not found»). В консоли — ошибка: запрос GET /users/me возвращает 401 Unauthorized, данные профиля не загружаются.
Проверка на уровне API: прямой запрос POST /users/login с теми же учётными данными возвращает 200 и валидный access_token. При этом последующий запрос GET /users/me из-под UI-сессии возвращает 401. Таким образом, вход и выдача токена работают корректно, а ошибка возникает на этапе передачи/использования токена при запросе данных профиля.

**Ожидаемый результат:**
Данные авторизованного пользователя загружаются; в меню отображается имя пользователя, запрос `/users/me` возвращает 200 с данными профиля.

## BUG-009: Пример успешного ответа (200) в документации GET /products/{id} описывает структуру бренда вместо товара
| Поле | Значение |
| --- | --- |
| **Компонент** |	API, документация (Swagger) |
| **Severity** |	Minor |
| **Priority** | Low |
| **Окружение** |	Swagger UI, https://api-with-bugs.practicesoftwaretesting.com/api/documentation |
|**Эндпоинт**| 	GET /products/{productId} |
| **URL** |	Swagger UI, https://api-with-bugs.practicesoftwaretesting.com/api/documentation |
| **Воспроизводимость** | Всегда |

**Предусловия:**
Доступ к Swagger UI.

**Шаги воспроизведения:**
1. Открыть Swagger UI, эндпоинт GET /products/{productId}.
2. В блоке Responses раскрыть код 200, посмотреть Example Value.
3. В поле productId ввести 1, нажать Execute.
4. Сравнить Example Value из документации с фактическим телом ответа.

**Фактический результат:**
Документированный пример для 200 содержит структуру объекта Brand: { "id": 0, "name": "new brand", "slug": "new-brand" }. Фактический ответ на id=1 содержит структуру товара: id, name («Combination Pliers»), description, price, category_id, brand_id, вложенные объекты product_image и category. Структура примера в документации не соответствует реальному ответу эндпоинта. Примеры для кодов 404 и 405 при этом корректны.

**Ожидаемый результат:**
Example Value для 200 отражает фактическую структуру товара, возвращаемую эндпоинтом (id, name, description, price, category, brand, product_image и т.д.).
