# Тест-план: Toolshop (Practice Software Testing, версия с багами)

## 1. Введение
Данный тест-план описывает подход к тестированию веб-приложения Toolshop -
интернет-магазина инструментов, предназначенного для практики тестирования
(используется сборка с намеренно заложенными дефектами).

Документ определяет цели и границы тестирования, виды тестирования, тестовое
окружение, а также критерии начала и завершения работ.

## 2. Объект тестирования
Тестируется веб-приложение Toolshop (версия с намеренно заложенными дефектами).

- Приложение: https://with-bugs.practicesoftwaretesting.com
- API: https://api-with-bugs.practicesoftwaretesting.com
- Документация API (Swagger): https://api-with-bugs.practicesoftwaretesting.com/api/documentation

**Технологический стек:**

| Слой | Технологии |
| --- | --- |
| Backend | Laravel 12, PHP 8.3 |
| Frontend | Angular 20, Bootstrap 5 |
| База данных | MariaDB 10.6 |
| Инфраструктура | Docker, Nginx, PHP-FPM |
| Тестирование (внутреннее) | Pest, Playwright, Pact |

## 3. Цели тестирования
Оценить соответствие фактического поведения приложения ожидаемому,
Выявить и зафиксировать дефекты в баг-репортах.

## 4. Границы тестирования (Scope)
### Что входит в тестирование
- Каталог товаров: список, карточка товара, похожие товары
- Поиск и фильтрация (по категории, бренду, цене)
- Корзина и оформление заказа
- Регистрация, авторизация, профиль пользователя
- Избранное
- Форма обратной связи
- UI/UX и визуальные проверки (вёрстка, подписи, опечатки)

### Что НЕ входит в тестирование
- Нагрузочное и performance-тестирование
- Тестирование безопасности
- Тестирование локального развёртывания (Docker) и исходного кода
- Кросс-браузерное и мобильное тестирование
- Автоматизированное тестирование (вне текущего этапа)
- Базовые проверки REST API (через Swagger / Postman)


## 5. Виды тестирования
- Функциональное тестирование — проверка корректности работы функций магазина
  (каталог, корзина, оформление заказа, авторизация).
- UI/UX тестирование — проверка вёрстки, отображения элементов, подписей,
  корректности текста (опечатки, обрезанные надписи).
- Исследовательское тестирование — свободное изучение приложения без заранее
  заданных шагов с целью найти неочевидные дефекты.

## 7. Критерии входа и выхода
### Критерии входа
- Приложение доступно и работоспособно (сайт открывается).
- Изучена документация приложения.
- Определён объём тестирования и подготовлено тестовое окружение.

### Критерии выхода
- Пройдены все запланированные проверки (чек-листы / тест-кейсы).
- Выявленные дефекты задокументированы в баг-репортах.

## 8. Риски
- Тестовые аккаунты являются общими: другие пользователи могут одновременно
  изменять данные, что может исказить результаты проверок.
- Данные на учебном стенде периодически сбрасываются, что может влиять
  на воспроизводимость дефектов.
- Приложение развёрнуто на публичном учебном хостинге — возможны замедления
  или недоступность, не связанные с дефектами самого приложения.
